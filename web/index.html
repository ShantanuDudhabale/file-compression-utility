Understanding Amdahl's Law in File Compression:

Amdahl's Law defines the maximum theoretical speedup \(S(N)\) when using \(N\) parallel processor cores:

Speedup(N) = 1 / [ (1 - P) + (P / N) ]

• Parallel Fraction (P ≈ 92-95%): Chunk compression routines running in parallel across worker threads.
• Serial Fraction (1 - P ≈ 5-8%): File opening, reading input bytes from disk, writing the PCMP archive header, and synchronizing threads.
• Why Speedup Flattens: Even with infinite CPU cores, overall execution speed is ultimately bound by disk I/O and thread creation overhead.

Operating Systems Concepts & Viva Examination Prep
Viva Reference

Key Operating Systems theory, architectural questions, and answers demonstrated by this project for your course viva and evaluation:

1. How does multithreading work in this project? ▼
Architecture: The main thread acts as an OS Coordinator. It reads the input file into memory in discrete chunks (e.g., 1024 KB). For each batch of chunks, it creates a pool of POSIX threads using pthread_create().
Each worker thread runs compress_worker(), executing the zlib DEFLATE algorithm independently on its designated memory buffer.
The main thread then uses barrier synchronization via pthread_join() to wait for all workers to finish before writing the compressed chunks to the PCMP archive in strict sequential order.
2. Why does changing the thread count change speed, but not compression ratio? ▼
Core Principle: Threads provide concurrency and throughput, not algorithmic compression. Each thread runs the exact same compression algorithm (compress2()) at the same compression level on its assigned chunk.
Whether 1 thread compresses 4 chunks one after another or 4 threads compress them at the same time, the compressed bytes produced for each chunk remain identical. Concurrency reduces total wall-clock time, not output file size.
3. How does this project prevent Race Conditions and Deadlocks? ▼
Zero Shared Mutable State: Each worker thread is given its own disjoint input and output memory buffers: tasks[i].in_data = in_buf + (i * chunk_size) and tasks[i].out_data = out_buf + (i * cap).
Because no two threads read or write to the same memory addresses, no mutex locks are required during compression, completely eliminating race conditions, lock contention, and deadlocks.
Synchronization is cleanly enforced at the batch boundary using pthread_join().
4. Why do DOCX, ZIP, PNG, and JPG files achieve ~0% compression? ▼
Shannon's Source Coding Theorem: A .docx file is actually a zipped OpenXML container already compressed using DEFLATE. A .png file already has DEFLATE scanlines, and a .jpg uses DCT lossy compression.
Because these files have already reached near-maximum information entropy (almost zero remaining repetitive byte patterns), lossless DEFLATE cannot shrink them further. In fact, adding chunk metadata headers often causes a tiny expansion (+0.01% to +0.05%).
5. What is the PCMP archive header structure and how does it prevent attacks? ▼
The archive begins with a strictly packed 36-byte header: magic (4B "PCMP") | original_size (8B) | total_chunks (4B) | chunk_size (4B) | original_ext (16B).
Security & Integrity Checks: 1. Validates magic signature against "PCMP".
2. Enforces bounds: rejects archives if orig_len > chunk_size or comp_len > compressBound(chunk_size) to prevent buffer overflow attacks.
3. Verifies each chunk's 32-bit CRC32 checksum before writing restored bytes to disk.
6. How does Amdahl's Law apply to this system? ▼
Amdahl's Law states that speedup is limited by the non-parallelizable serial portion: S(N) = 1 / ((1 - P) + P/N).
In our program, file I/O (fread, fwrite), archive header creation, and thread dispatch represent the serial fraction \((1 - P)\). Even as thread count \(N\) scales to 8 or 16, total execution time approaches a floor dictated by disk I/O throughput.
